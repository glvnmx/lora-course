Настройка LoRA-адаптера в Hugging Face PEFT

Соберёте практический пайплайн: загрузка модели, LoraConfig, подключение адаптера, обучение через SFTTrainer и сохранение результата.

Прогресс лекцииПрогресс курса обновится после мини-теста

Базовый стек

Практический LoRA-пайплайн обычно строится на transformers, peft, datasets, trl и accelerate. transformers загружает модель и токенизатор, peft внедряет адаптер, trl даёт SFTTrainer, а datasets помогает готовить train/eval splits.

LoraConfig

Ключевые параметры: r, lora_alpha, lora_dropout, target_modules, bias и task_type. Для causal language modeling обычно используют task_type="CAUSAL_LM". Конфиг должен отражать задачу и ограничения памяти, а не просто копировать случайный пример.

Подготовка датасета

Для SFT важны чистые пары instruction/answer или диалоги с ролями. Нужно убрать дубликаты, проверить длины, привести формат к chat template и выделить validation split. Плохой датасет LoRA обучит быстро, но результат будет плохим так же быстро.

Сохранение адаптера

После обучения обычно сохраняют только adapter_config.json и adapter_model.safetensors. Это небольшой артефакт, который можно загрузить поверх той же базовой модели или слить с ней для простого inference.

Итоги лекции

  • PEFT подключает LoRA через LoraConfig и get_peft_model.
  • Важные параметры: r, alpha, dropout и target_modules.
  • Датасет для SFT должен быть чистым, согласованным и иметь validation split.
  • Сохраняют адаптер отдельно от базовой модели, чтобы упростить хранение и деплой.

LoRA Config Studio

сборка конфига без запуска Python
Результат проверки появится здесь.
from peft import LoraConfig

config = LoraConfig(
    r=16,
    lora_alpha=32,
    lora_dropout=0.05,
    target_modules=["q_proj", "v_proj"],
    task_type="CAUSAL_LM",
)
print(config.r, config.target_modules)
