Как настроить LoRA через Hugging Face PEFT

Hugging Face PEFT превращает LoRA из идеи в воспроизводимый pipeline: загрузили base model, описали LoraConfig, обернули модель, обучили и сохранили adapter.

Зачем это нужно в работе

В продуктовой работе важно не только обучить модель, но и оставить понятный путь воспроизведения: какие версии, какие параметры, какие артефакты и где лежит адаптер.

Подробное объяснение простым языком

PEFT отделяет базовую модель от адаптера. Base model загружается из Transformers, LoraConfig описывает, какие LoRA-ветки добавлять, get_peft_model создаёт обучаемую обёртку. После обучения save_pretrained сохраняет только adapter files.

Такой pipeline дисциплинирует эксперимент: конфиг становится явным, trainable parameters проверяются до запуска, а результат можно подключить к той же базовой модели позже.

Технический блок

Минимальный путь: AutoModelForCausalLM.from_pretrained → LoraConfig → get_peft_model → train → model.save_pretrained("adapter"). Для inference используют PeftModel.from_pretrained(base_model, adapter_path).

Типичные ошибки

  • Не сохранять tokenizer/config рядом с инструкцией запуска.
  • Забывать task_type="CAUSAL_LM" для causal LLM.
  • Не фиксировать версии datasets, transformers и peft в README проекта.

Мини-кейс ML/LLM-инженера

Команда просит повторить эксперимент через месяц. Благодаря сохранённым LoraConfig, seed, base revision и eval prompts другой инженер запускает тот же pipeline и получает сопоставимый результат.

Короткое резюме

  • PEFT pipeline должен быть воспроизводимым.
  • Сохраняется маленький adapter, а не полная модель.
  • README проекта должен объяснять, как подключить адаптер к базе.
