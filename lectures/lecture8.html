Зачем это нужно в работе

Модельный эксперимент становится полезным только тогда, когда его можно передать другой команде. Публикация — это не кнопка upload, а упаковка артефактов, лицензий, ограничений и инструкции запуска.

Подробное объяснение простым языком

Adapter-first подход хранит base model отдельно, а LoRA подключает во время inference. Это удобно, когда у вас несколько задач или нужно быстро переключаться. Merge-and-unload сливает адаптер в веса модели, что может упростить inference, но усложняет хранение нескольких версий.

Публикация должна явно связывать адаптер с базой: имя модели, revision, task, данные, ограничения, eval и пример запуска. Без этого adapter_model.safetensors почти бесполезен для другого инженера.

Типичные ошибки

  • Публиковать адаптер без указания base model.
  • Не описывать ограничения датасета и известные ошибки.
  • Сливать адаптер с базой, когда продукту нужны быстрые переключения между задачами.

Мини-кейс ML/LLM-инженера

Команда выкладывает адаптер для JSON-извлечения, но забывает base revision. Через две недели inference ломается на новой версии базы. После добавления model card и pin revision проект становится воспроизводимым.

Короткое резюме

  • Публикация фиксирует связь adapter ↔ base model.
  • README должен показывать запуск, eval и ограничения.
  • Выбор adapter-first или merged зависит от деплоя и числа задач.
