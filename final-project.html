Выбор задачи и данных

Цель этапа

Цель этапа — сузить задачу до сценария, который можно проверить за короткий LoRA-эксперимент.

Что нужно сделать

Выберите пользователя, формат ответа, 20-100 чистых примеров, train/eval split и baseline-ответы base model.

Пошаговый план

  1. Опишите продуктовый сценарий.
  2. Зафиксируйте желаемый формат ответа.
  3. Подготовьте JSONL.
  4. Разделите train/eval.
  5. Сохраните baseline.

Пример результата

После вкладки у вас есть понятное решение и проверяемые файлы, которые можно показать ревьюеру проекта.

Артефакты

task.md, data/train.jsonl, data/eval.jsonl, baseline_examples.md, data/README.md

Частые ошибки

Слишком широкая задача; нет baseline; train и eval пересекаются; данные содержат противоречивые ответы.

Конфигурация LoRA

Цель этапа

Цель этапа — объяснить, почему выбранные target_modules, rank, alpha и dropout соответствуют задаче и данным.

Что нужно сделать

Выберите base model, проверьте архитектуру, задайте target_modules, r/alpha/dropout, решите нужен ли QLoRA.

Пошаговый план

  1. Зафиксируйте base model revision.
  2. Найдите имена modules.
  3. Выберите стартовый r.
  4. Запишите memory budget.
  5. Проверьте trainable parameters.

Пример результата

После вкладки у вас есть понятное решение и проверяемые файлы, которые можно показать ревьюеру проекта.

Артефакты

configs/lora_config.json, configs/model_card_notes.md, config_rationale.md

Частые ошибки

Копирование чужих target_modules; слишком высокий rank на маленьких данных; нет объяснения alpha/dropout.

Обучение

Цель этапа

Цель этапа — запустить воспроизводимое обучение и сохранить параметры так, чтобы эксперимент можно было повторить.

Что нужно сделать

Опишите batch, accumulation, sequence length, learning rate, epochs/steps, seed, logging и сохранение checkpoints.

Пошаговый план

  1. Проверьте датасет.
  2. Запустите короткий smoke run.
  3. Запустите training.
  4. Следите за train/eval loss.
  5. Сохраните adapter.

Пример результата

После вкладки у вас есть понятное решение и проверяемые файлы, которые можно показать ревьюеру проекта.

Артефакты

train_config.yaml, training_log.md, adapter_config.json, adapter_model.safetensors

Частые ошибки

OOM решают хаотично; нет seed; eval loss не логируется; сохранён только ноутбук без параметров.

Оценка качества

Что нужно сделать

  2. Прогоните baseline.
  3. Прогоните adapter.

Публикация

Цель этапа

Цель этапа — оформить адаптер как передаваемый ML-артефакт: понятный, воспроизводимый и проверяемый.

Что нужно сделать

Соберите README, model card, ссылки на base model, инструкции загрузки, ограничения данных, eval и примеры.

Пошаговый план

  1. Проверьте adapter files.
  2. Укажите base revision.
  3. Добавьте пример PeftModel.from_pretrained.
  4. Опишите eval.
  5. Подготовьте репозиторий или Hugging Face card.
